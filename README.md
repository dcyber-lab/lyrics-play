# Lyrics Live

去现场听歌时用的歌词滚动网页：按 setlist 建歌单，进场前缓存好，现场跟着乐队滚动，偶尔点一下校准。

## 怎么用

1. 首页「预设歌单」里点导入，会在手机上从 LRCLIB 拉歌词（预设只存歌名/歌手/时长，在 `src/presets.js`）；或者新建歌单，从 [LRCLIB](https://lrclib.net) 搜歌，或者把整场 setlist 粘进「批量」里（每行一首）
2. 进场前在 Safari 里打开一次，「分享 → 添加到主屏幕」，之后离线也能用
3. 现场：**歌手开口时点那一行**，歌词就从这里开始走
4. 对不上了就再点当前在唱的那一行。两次点击间隔够长的话，会顺便学到乐队的实际速度（现场通常比录音室版快或慢几个百分点）
5. 细调用 ½ 秒回退 / 前进，点速度按钮可以手动拖动调速
6. 右上角两个按钮：**演出模式**把顶栏和控制栏都藏起来，只剩大字歌词（照样可以点行校准）；**锁**会盖住整个屏幕，挡掉所有点击和滑动，只有长按锁图标才能解锁
7. **相机模式**（顶栏相机图标）：用摄像头实时画面当背景，歌词变成画面下方的字幕。配合 iOS 控制中心的「屏幕录制」，就能录出带歌词的现场视频。几秒不碰屏幕，控制条会完全隐藏；可以切前后摄像头
8. 屏幕常亮：优先用 Wake Lock API，拿不到时自动换成循环播放一段静音小视频的老办法

没有时间轴的歌词（标「估算」）会按歌长均匀铺开，多点几下就能跟上。

导入时没找到的歌会记在歌单里，在歌单页可以重试、手动搜（搜到的歌会放回原来的位置），或者直接移除。

## 分享和打轴

- **分享歌单**：歌单页右上角的分享按钮会生成链接和二维码。链接里只有歌名、歌手和时长（压缩后 40 首约 700 字符），朋友打开以后在他自己手机上拉歌词。Safari 版和主屏幕版之间互传歌单也可以用这个。
- **演出卡片**：同一个面板的第二页，生成 1080×1920 的快拍图，包含日期、场馆和曲目。演出时在播放页点过的歌会按日期记下来，卡片默认只列当晚唱过的歌。
- **打轴**：标着「估算」的歌，可以从播放页的标签或编辑模式进入打轴页。在 Spotify / Apple Music 放原曲，每句开口唱时点一下，就能生成真正的 LRC 时间轴。

## 封面和歌手照片

专辑封面和歌手照片来自 Deezer（通过 JSONP 调用，因为它不带 CORS 头），Deezer 没有封面时用 iTunes 补上。库里只存图片 URL，图片本身由 Service Worker 缓存在单独的 `lyrics-live-img` 缓存里，发新版本时不会被清掉。歌单页会显示「图片已离线 n/m」，进场前确认一下是满的。

## 耗电

播放页按需刷新：算好下一句开始的时刻再刷新，其余时间每秒刷新一次，暂停时完全不刷新；只有相机模式的逐词填色才保持每秒 10 次。背景是静止的，不放无限循环的动画，这样 ProMotion 屏幕可以把刷新率降下来。

在 Chromium 里测（主线程 CPU）：普通播放从约 3.0 秒/分钟降到 1.2 秒/分钟，暂停时从 0.46 降到 0.16，换行时机误差约 17ms。真正耗电的大头是屏幕亮度，以及相机模式下的摄像头。

## 同步原理

`src/lib/clock.js` 里的 `SyncClock`：歌词位置 = 锚点 + 经过的时间 × rate。每次点某一行就是一次观测，含义是“此刻唱到这里了”。两次观测之间的歌词时间差除以真实时间差，就是实测速度，按权重混进 rate。下面三种情况会忽略这次观测：跨度太短（误差大）、差得离谱（大概率是跳段或重复副歌）、中间暂停过（MC 时间会污染测量）。

## 开发

```sh
npm install
npm run dev      # 本地开发
npm test         # 单元测试
npm run build    # 输出到 dist/
```

推到 `main` 后，`.github/workflows/deploy.yml` 会自动部署到 GitHub Pages（需要在仓库 Settings → Pages 里把 Source 设成 GitHub Actions）。
